## Fixing now: uploads fail on the demo (2026-10-09)

The owner reported: "I can't upload docs; I keep getting an error." Branch `fix/p4-uploads` in
all three repos. Findings so far:

1. **Root cause — the app containers have no AWS credentials.** `deploy/demo/compose.yaml`
   (Phase 4) says "the server's IAM role signs every request", but since Phase 1 the instance
   sets `http_put_response_hop_limit = 1` (`terraform/dev/demo.tf`): IMDSv2 answers can't reach
   a Docker container, by design. So the api, worker and transcriber can't sign any S3 call:
   `POST /uploads` fails at `CreateMultipartUpload` (500, "Something went wrong on our side"),
   and reading pages, peaks and sample files fails too. The deploy stayed green because the
   api's readiness check doesn't include storage.
2. The bucket CORS rule and `ListMultipartUploadParts` (Phase 4 Terraform) only exist once the
   owner runs `terraform apply`; without CORS the browser's part PUTs are blocked as well.

Fix plan: a scoped IAM user for the app's file access (keys generated by Terraform into SSM
`/sotto/demo/S3_*`, passed to api/worker/transcriber; containers still can't reach the instance
role), ADR 0018; storage in the api's readiness check so a deploy can't go green without it;
clearer storage errors. Then the owner runs `terraform apply` and re-runs `deploy-config`.
**Demo:** deployed from `main` by the `images` workflows (`terraform output demo_url` prints the address)
